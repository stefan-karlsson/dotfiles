# A channel is enrolled the way its vendor enrolls it, and shared packages are named

A repository is declared the way its vendor's own package writes it, and a package that more than one enrolled channel carries is declared as shared. Both rules live in the repository data.

A vendor package that rewrites its own apt source at install and upgrade wins over anything this source state writes to the same file. Microsoft Edge's `postinst` recreates `/etc/apt/sources.list.d/microsoft-edge.sources` with `packages.microsoft.com/repos/edge-stable` and its own keyring. The declared channel matches what that script writes, including the keyring path — the same Microsoft release-signing key the rest of this setup pins, in a second file. A repeated field in the stanza that script generates is read as the single field apt reads it as.

`packages.microsoft.com/ubuntu/26.04/prod`, enrolled for the Intune Portal, also carries `kubectl` with a version string that outranks the Kubernetes channel's. Apt takes Microsoft's build on a company laptop and the Kubernetes project's build everywhere else. `kubectl` is declared as shared rather than held to one channel: both channels are enrolled here, each has its key pinned, and the builds are of the same upstream Kubernetes release. An apt preference forcing one of them is a downgrade in apt's terms, which apt refuses inside a batch install. The preflight asks of a shared package that its installed version come from some channel this source state enrolled, rather than from the one repository that names it.
